### 🔴 [紧急待办] 管理员必须在 3 小时后（或业务低峰期）执行的操作
1. **修改 MySQL 预编译语句上限 (解决 ER_MAX_PREPARED_STMT_COUNT_REACHED 导致支付/审核 500 报错崩溃)**
   - 登录线上宝塔面板 -> 软件商店 -> MySQL -> 设置 -> **配置修改 (my.cnf)**。
   - 在 `[mysqld]` 模块下方找个空行，添加：`max_prepared_stmt_count = 1048576`
   - **保存并重启 MySQL 服务**。（注意：重启瞬间数据库会断开，请务必在低峰期操作）。
2. **恢复 ESA (阿里云加速) 的 API 绕过缓存策略**
   - 必须在重启完 MySQL 后，去阿里云 ESA 控制台 -> 缓存规则 -> 将 `/api/` 路径的规则重新改为 **“绕过缓存 (Bypass Cache)”**，以确保中东用户能实时获取最新数据。
3. **彻底关闭 MySQL 的 DNS 逆向解析 (解决频繁超时断流)**
   - 同样在宝塔 MySQL 的 `my.cnf` 中添加：`skip-name-resolve`。能瞬间消灭 `Aborted connection` 日志，极大提升 Node.js 连库速度。

### ✅ 已完成的所有核心修复与代码更改记录

#### 一、 数据库与并发架构优化
1. **彻底消除高并发死锁与长事务阻塞** (修改: `app/service/task.js`)
   - **操作**：将 `search` (抢单) 接口中最耗时的商品查询（`GoodsTask.findOne`）移出排他锁 (`transaction`)，锁的生命周期缩短至 1 毫秒内极速 `commit`。彻底杜绝大面积死锁白屏。
2. **数据库查询极限瘦身 95%** (修改: `app/service/task.js`)
   - **操作**：为抢单查询添加了 `attributes: ['id', 'goods_name', 'goods_price', 'goods_images']`。丢弃臃肿的 HTML 富文本，极大降低内存占用和弱网截断概率。
3. **高并发连接池打爆修复** (修改: `app/service/task.js`)
   - **操作**：将 `getUserTaskInfo` 里的高并发 `Promise.all` 拆解为串行 `await` 查询，防止瞬间打爆 MySQL 连接池引发 `ECONNRESET`。

#### 二、 底层网络抗弱网极限优化 (中东地区专项)
4. **Node.js 传输层极限保活** (修改: `config/config.default.js`)
   - **操作**：全局开启 `Gzip` 压缩（API 数据包缩减 80%）。
   - **操作**：将 `serverTimeout`, `keepAliveTimeout`, `headersTimeout` 全部放宽至 **120秒**，防止低端安卓因发包过慢被系统掐断。
   - **操作**：`bodyParser` 负载上限放宽至 `10mb`。
5. **Sequelize 底层自动重试与连接池调优** (修改: `config/config.default.js`)
   - **操作**：连接池最大连接数提至 `200`，允许排队等待 `60000ms`，空闲释放延长至 `30000ms`。
   - **操作**：开启 `retry` 机制，遇到 `ECONNRESET` 和 `Deadlock` 自动静默重试 3 次。
   - **操作**：增加 `query: { typeCast: true }` 防止并发下的预编译语句（Prepared Statement）泄露。

#### 三、 代理穿透与防缓存机制
6. **ESA (阿里云CDN) 双层代理穿透** (修改: `config/config.default.js`)
   - **操作**：设置 `maxProxyCount = 2` 和 `maxIpsCount = 2`，穿透 ESA 拿到中东真实 IP，防止全局拦截中间件发生误杀。
7. **全局跨域与防缓存中间件** (修改: `app/middleware/mobile_no_cache.js`)
   - **操作**：强制注入 `proxy-revalidate`、`no-store` 及宽容的 CORS 放行头，穿透海外运营商代理。
8. **新增防缓存专用 POST 接口** (修改: `app/router.js`)
   - **操作**：增加 `POST /api/mobile/getUserTaskInfoSync` 和 `POST /api/mobile/missions/searchSync`。利用 POST 天然不缓存的特性，绕过 TG 安卓端的死缓存。

#### 四、 业务逻辑与脏数据修复
9. **订单号类型冲突导致的幽灵回滚** (修改: `app/service/*.js` 全局)
   - **操作**：清理了 `task`, `admin_outer_customer`, `sys_log`, `user`, `goods`, `shop` 中所有订单号/流水号生成逻辑。去除了 `T`, `BL`, `L` 等字母前缀，统一改为**纯 16 位数字字符串**，完美兼容 `BIGINT` 字段，杜绝写入崩溃。
10. **时区切割错误与脏数据自愈** (修改: `app/service/task.js`)
    - **操作**：修复了时区 `setDate(-1)` 导致的“昨天/今天”幽灵数据，改用时间戳绝对计算。
    - **操作**：增加了状态机自愈逻辑，遇到 `status=0 & task_status=1` 的卡死脏数据自动修复为 2（已完成）并放行。
11. **修复财务黑洞与 TG 误导日志** (修改: `app/service/recharge_request.js`, `withdraw.js`, `telegram.js`)
    - **操作**：在充值审核通过、提现驳回的事务中，**补齐了写入 `UserWalletLog` (资金明细) 的逻辑**，解决财务死账问题。
    - **操作**：将 Telegram 消息发送改为 `ctx.runInBackground`，加入 2 秒超时快速掐断，并使用 `ctx.app.logger` 消灭了附带 `5031ms` 误导时间的假阻塞日志。

#### 五、 阿里云 ESA (全球加速) 终极配置记录
为了彻底解决中东地区网络极差、高延迟以及 CDN 缓存导致的数据不更新问题，以下 ESA 最佳实践配置已确认：
12. **网络与 TLS 加速配置**
    - **SSL/TLS 模式**：设置为 `Full (Strict)` / `完全严格`。确保回源全程加密，防止跨国链路被劫持篡改。
    - **HTTP/3** 与 **0-RTT**：全部 `开启`。让中东高延迟网络下的老用户跳过握手，极大降低 API 延迟。
    - **回源保持连接 (Origin Keep-alive)**：必须 `开启`。让 ESA 节点和香港服务器保持长连接，配合代码中的 `keepAliveTimeout: 120000`，彻底消灭 `ECONNRESET` 断流。
13. **API 动态数据绕过缓存规则**
    - **匹配规则**：`URI 路径` `开头为` `/api` (即 `starts_with(http.request.uri.path, "/api")`)。
    - **执行动作**：设置缓存资格为 `绕过缓存 (Bypass Cache)`。确保所有动态接口实时回源，杜绝死缓存白屏。

## 1. 数据库规范 (核心规则)

> **注意：** 此部分是专门用于 AI 引入上下文的数据库架构文档。开发人员与AI必须严格遵循以下规则：

### 1.1 数据库核心约束

1. **不可随意在线上创建表**：创建表，都需要停止，提示是否添加表。
2. **用户必须存在sys_user表里**：ABC3端的所有用户必须存在 `sys_user` 表里，没有特定要求不新建表。
3. **维护没有的表需要询问**：如果代码里还有维护没有的表，就要标注给我询问，不准直接去创建表。
4. **严禁主观臆断表结构**：严禁在未查看此文件的情况下主观臆断表结构，确保所有外键关联（如 `user_id`, `shop_id`, `category_id`）准确无误。
5. **同步更新此文件**：如果在开发过程中新增了表，或修改了现有表的核心字段/关联关系，**必须同步更新本文件**，以保持架构文档的绝对一致性。
6. **遵循文档进行数据库开发**：接口涉及到数据库的，**必须严格根据本文档内有说明的数据库表格进行开发**，严禁使用本文档未说明的废弃表。
7. **仅操作线上数据库**：所有涉及数据库的操作（包括增删改查、迁移同步等）都是在操作线上服务器的数据库，**严禁在本地数据库进行任何操作**。
8. **强制使用表名常量**：使用新的数据表**必须在 `app/constant/table_names.js` 内命名好，统一使用**。如果在开发或重构过程中，发现还有直接硬编码使用表名字符串的地方，必须修改为统一从常量文件获取。
9. sys_user `1=A端管理员，2=B端店长，3=B端业务员，4=C端普通用户`

## 3. AI 助手执行准则 (Checklist)

每次用户唤起 `#核心规范合集` 并派发新任务后，AI 必须在脑海中完成以下 Checklist：

- [ ] 我是否已经读取了上述两个补充 `.md` 文件？
- [ ] 我接下来要写的代码，其操作的数据库表是否在《核心规范合集》中有定义？字段名是否完全一致？
- [ ] 如果我要写关联查询 (`include`) 或 `where` 条件，我是否已经用工具查看了实际的 `app/model/xxx.js` 文件确认了主键和字段名？
- [ ] 我新增的接口参数是否全部使用了 `snake_case`？
- [ ] **数据表名是否已经使用了 `app.TableNames.XXX` 常量，而不是硬编码字符串？**
- [ ] 代码写完后，我是否进行了 `node -c` 语法检查？
- [ ] 如果我启动了 `npm run dev` 测试，我在回复用户前，是否已经强杀了占用 7001 端口的 Node 进程？
- [ ] 我是否按照模板，把新接口补充到了对应的 `.gf` 接口文档中？
- [ ] 如果我修改了任何一端接口，我是否在《三端接口重构进度.md》中更新了它的完成状态？

只要严格遵守本合集约束，就能极大地提高开发效率，避免无效的返工和报错修复。

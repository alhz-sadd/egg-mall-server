# 店铺管理接口 (Admin-Inner)

新建店铺需要给店铺新建默认配置，比如vip，默认配置，等
店铺本身不需要登录
只有底下的店长需要可以登录
新建店长&业务员，是新建在sys_user

## 1. 获取所有启用店铺 (下拉框专用)

用于在新建商家、分配业务员等场景时，供前端下拉框选择归属店铺。

- **接口地址**: `GET /api/admin-inner/shops/all`
- **请求方式**: `GET`
- **请求头**:
  - `Authorization`: `Bearer <token>`
- **请求参数**: 无
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "获取成功",
  "data": [
    {
      "shop_id": 1,
      "shop_name": "测试店铺A",
      "shop_no": "SH20260905001"
    },
    {
      "shop_id": 2,
      "shop_name": "测试店铺B",
      "shop_no": "SH20260905002"
    }
  ]
}
```

        "create_time": "2026-09-05T10:00:00.000Z"

- **接口地址**: `GET /api/admin-inner/shops/:shop_id/setting`

- **说明**: URL 参数 `shop_id` 为目标店铺的ID。

## 5. 修改店铺业务配置 (shop_setting)

- **接口地址**: `PUT /api/admin-inner/shops/:shop_id/setting`
- **请求方式**: `PUT`
- **说明**: URL 参数 `shop_id` 为目标店铺的ID。
- **请求参数 (Body)**: (全部为可选字段，传入即修改)
  - `real_name_reward`: number (实名奖励金额)
  - `order_pay_timeout_switch`: integer (0关闭 1开启)
  - `order_pay_timeout`: integer (超时时间，单位秒)
  - `withdraw_min_amount`: number (提现最小金额)
  - `withdraw_fee_type`: integer (1固定金额，2百分比)
  - `withdraw_fee_value`: number (提现佣金)
  - `withdraw_first_need_task`: integer (0不需要，1需要)
  - `withdraw_first_need_identity`: integer (0不需要，1需要)
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "更新成功",
  "data": {
    ... 更新后的配置数据 ...
  }
}
```

## 6. 获取员工 (店长/业务员) 列表

- **接口地址**: `GET /api/admin-inner/employees`
- **请求方式**: `GET`
- **说明**: 获取员工列表。如果是商家(user_type=2)或业务员(user_type=3)登录，只能看到自己店铺下的员工；如果是管理员，则可以查询所有。
- **请求参数 (Query)**:
  - `keyword`: string (可选，用户名/昵称/手机号模糊搜索)
  - `user_type`: integer (可选，2:店长, 3:业务员。如果不传，则返回2和3)
  - `status`: integer (可选，状态：0禁用 1启用)
  - `page`: integer (默认 1)
  - `page_size`: integer (默认 10)
  - `shop_id`: integer (可选，按店铺筛选，管理员可用)
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "list": [
      {
        "user_id": 1,
        "username": "sales_01",
        "nickname": "张业务",
        "phone": "13800000000",
        "user_type": 3,
        "shop_id": 1,
        "status": 1,
        "create_time": "2026-09-05T12:00:00.000Z",
        "shop_name": "测试店铺A",
        "shop_no": "SH20260905001"
      }
    ],
    "pagination": {
      "total": 1,
      "page": 1,
      "page_size": 10,
      "total_pages": 1
    }
  }
}
```

## 7. 新增员工 (店长/业务员)

- **接口地址**: `POST /api/admin-inner/employees`
- **请求方式**: `POST`
- **说明**: 通过 `user_type` 区分是创建店长还是业务员。如果当前登录不是管理员，则会自动使用其所在店铺的 `shop_id`，否则需要指定 `shop_id`。如果创建店长且传入了 `shop_name`，还会自动创建对应的店铺。
- **请求参数 (Body)**:
  - `username`: string (必填，账号)
  - `password`: string (必填，密码)
  - `user_type`: integer (必填，2:店长, 3:业务员)
  - `nickname`: string (可选，昵称)
  - `phone`: string (可选，手机号)
  - `email`: string (可选，邮箱)
  - `avatar`: string (可选，头像)
  - `shop_id`: integer (可选，归属店铺ID)
  - `shop_name`: string (可选，如果创建店长且不传 shop_id，则可通过该字段新建店铺)
  - `shop_no`: string (可选，新建店铺时必填的店铺编号)
  - `role_id`: integer (可选，角色ID)
  - `status`: integer (可选，0禁用 1启用，默认 1)
  - `remark`: string (可选，备注)
  - `recharge_address`: string (可选，如果为业务员可设置其默认充值地址)
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "创建成功",
  "data": {
    "user_id": 2,
    "username": "sales_02",
    "user_type": 3,
    "shop_id": 1
  }
}
```

## 8. 修改员工 (店长/业务员)

- **接口地址**: `PUT /api/admin-inner/employees/:id`
- **请求方式**: `PUT`
- **说明**: URL 参数 `id` 为要修改的员工 `user_id`。
- **请求参数 (Body)**: (全部为可选，传了即修改)
  - `nickname`: string (昵称)
  - `phone`: string (手机号)
  - `email`: string (邮箱)
  - `avatar`: string (头像)
  - `shop_id`: integer (归属店铺ID)
  - `role_id`: integer (角色ID)
  - `status`: integer (状态：0禁用 1启用)
  - `remark`: string (备注)
  - `recharge_address`: string (业务员的默认充值地址)
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "更新成功",
  "data": {
    "user_id": 2,
    "username": "sales_02"
  }
}
```

## 9. 删除员工 (店长/业务员)

- **接口地址**: `DELETE /api/admin-inner/employees/:id`
- **请求方式**: `DELETE`
- **说明**: 软删除员工。如果删除的是店长(user_type=2)，会级联删除店铺及店铺下所有业务员和客户。
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "删除成功"
}
```

## 10. 新增店铺 (A端)

- **接口地址**: `POST /api/admin-inner/merchants`
- **请求方式**: `POST`
- **说明**: 平台管理员创建一个新的店铺。系统会自动为新店铺同步平台默认的 VIP 模板、基础参数配置、提现/充值渠道模板。**当前已简化，无需同时创建登录账号。**
- **请求参数 (Body)**:
  | 字段名 | 类型 | 必填 | 描述 |
  | :--- | :--- | :--- | :--- |
  | shop_name | string | 是 | 店铺名称 |
  | contact_person | string | 否 | 店铺联系人 |
  | contact_phone | string | 否 | 联系电话 |
  | status | integer | 否 | 店铺状态 (0:禁用, 1:启用, 默认1) |
  | remark | string | 否 | 备注信息 |
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "店铺创建成功",
  "data": {
    "shop_id": 10,
    "shop_name": "新开店铺",
    "shop_no": "SH1726112345678"
  }
}
```

## 11. 删除店铺 (深度级联清理)

- **接口地址**: `DELETE /api/admin-inner/merchants/:id`
- **请求方式**: `DELETE`
- **说明**: 深度清理店铺及其关联的所有数据。
- **清理范围**: 
  - **用户**: 该店铺下的所有商家、店长、业务员、C端用户 (软删除 `is_deleted: 1`)。
  - **配置**: 店铺配置、VIP等级、支付渠道模板 (物理删除)。
  - **业务**: 商品、任务、客户关系、充值提现订单 (物理删除)。
  - **日志与资产**: 关联用户的操作日志、登录日志、钱包资产及流水 (物理删除)。
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "删除成功，已清理店铺相关的所有数据及关联用户"
}
```

## 12. 获取商家/店铺列表 (A端)

- **接口地址**: `GET /api/admin-inner/merchants`
- **请求方式**: `GET`
- **说明**: 以店铺为中心返回列表，包含已绑定商家账号的店铺和未绑定账号的新店铺。
- **请求参数 (Query)**:
  - `keyword`: string (可选，模糊搜索店铺名称、编号、联系人)
  - `status`: integer (可选，店铺状态：0禁用 1启用)
  - `page`: integer (默认 1)
  - `page_size`: integer (默认 10)
- **返回数据结构**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [
      {
        "shop_id": 10,
        "shop_name": "新开店铺",
        "shop_no": "SH1726112345678",
        "contact_person": "张三",
        "contact_phone": "13800000000",
        "status": 1,
        "username": "merchant01", // 绑定的商家账号，未绑定则为 null
        "role_name": "商家",
        "children": [ ... ] // 该店铺下的业务员列表
      }
    ],
    "pagination": {
      "total": 1,
      "page": 1,
      "page_size": 10,
      "total_pages": 1
    }
  }
}
```

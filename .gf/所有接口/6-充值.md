# 充值管理模块

A端不参加
B端接收C端发起的请求，做成充值列表，可以通过审核，审核失败
C端1需要先获取店铺充值配置，发起充值请求

> **⚠️ 核心业务声明与注意事项**：
>
> 1. **A端不参与**：充值审核业务完全下放到 B 端，平台总后台不提供充值订单列表和审核接口。
> 2. **数据隔离机制**：
>    - 店长 (`isShopOwner === true`)：可以查看并审核该店铺下的所有充值订单。
>    - 业务员：只能查看并审核归属于自己的充值订单（即 `sales_user_id` 等于当前业务员 ID）。
> 3. **资金安全与原子性**：审核通过时，必须使用**数据库事务 (`transaction`)** 将更新订单状态、给用户钱包 `voucher_balance` 增加资产以及写入 `user_wallet_log` 流水三步操作包裹起来。
>
> **涉及的数据表**
>
> - `user_recharge`: 充值订单主表（新表，替代老的 recharge_order/recharge_request，存有凭证、手续费、渠道等信息）
> - `user_wallet`: 用户钱包表（审核通过后，给用户的 `voucher_balance` 加钱）
> - `user_wallet_log`: 钱包流水表（审核通过加钱时记录，biz_type 为 1充值）
> - `sys_user`: 账号表（关联查询用户基础信息和业务员信息）

## B端 (Admin-Outer) 商家/业务员操作

### 获取充值订单统计

- **路径**: `GET /api/admin-outer/recharge/stats`
- **描述**: 获取充值订单统计数据（总充值金额、今日充值金额、待审核数量）。店长看全店，业务员看自己。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数**: 无
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "获取成功",
    "data": {
      "total_amount": "1000.00",
      "today_amount": "100.00",
      "pending_count": 5
    }
  }
  ```

### 获取充值订单列表

- **路径**: `GET /api/admin-outer/recharge/list`
- **描述**: 获取充值订单列表。店长看全店，业务员看自己。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Query)**:| 字段名    | 类型   | 必填 | 描述                                             |

  | page      | int    | 否   | 页码                                             |
  | page_size | int    | 否   | 每页条数                                         |
  | status    | int    | 否   | 订单状态：1待审核，2审核通过，3审核驳回，4已取消 |
  | order_no  | string | 否   | 充值订单号                                       |

### 审核通过

- **路径**: `POST /api/admin-outer/recharge/:id/audit-success`
- **描述**: 审核通过用户的充值申请，并给用户钱包加钱。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:| 字段名     | 类型 | 必填 | 描述                           |
  | ---------- | ---- | ---- | ------------------------------ |
  | audit_type | int  | 是   | 审核类型：1真实充值，2虚拟充值 |
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "审核通过成功"
  }
  ```

### 审核驳回

- **路径**: `POST /api/admin-outer/recharge/:id/audit-fail`
- **描述**: 审核驳回用户的充值申请。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:| 字段名        | 类型   | 必填 | 描述     |
  | ------------- | ------ | ---- | -------- |
  | reject_reason | string | 是   | 驳回原因 |
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "审核驳回成功"
  }
  ```

## C端 (Mobile) 用户充值操作

### 获取当前绑定的业务员收款地址及店铺充值方式

- **路径**: `GET /api/mobile/recharge/sales-address`
- **描述**: C端用户获取为其服务的业务员配置的充值收款地址，以及归属店铺的充值方式。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数**: 无
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "获取成功",
    "data": {
      "sales_address": {
        "address": "Txxxxxxxxx...",
        "chain_type": "TRC20",
        "remark": "默认收款地址"
      },
      "shop_pay_channels": [
        {
          "id": 1,
          "shop_id": 1001,
          "channel_type": 1,
          "channel_code": "usdt_trc20",
          "channel_name": "USDT-TRC20",
          "is_platform_default": 1,
          "is_enable": 1,
          "sort": 0,
          "remark": ""
        }
      ]
    }
  }
  ```

### 提交充值凭证 (创建充值订单)

- **路径**: `POST /api/mobile/recharge/submit`
- **描述**: C端用户转账完成后，提交充值凭证创建新的充值订单 (`user_recharge` 表)。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:

| 字段名           | 类型   | 必填 | 描述                                   |
| :--------------- | :----- | :--- | :------------------------------------- |
| `channel_code` | string | 是   | 渠道编码，如 "usdt_trc20" 或 "default" |
| `amount`       | number | 是   | 充值金额，必须大于0                    |
| `voucher_img`  | string | 是   | 转账凭证图片URL                        |
| `remark`       | string | 否   | 备注                                   |

- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "充值申请已提交",
    "data": {
      "id": 101,
      "order_no": "RC178898990001",
      "status": 1
    }
  }
  ```

# 身份认证 (Admin-Outer / Mobile)

A端不需要
C端的需要用户上传姓名，证件号，证件正面照，证件反面照
B端 列表获取，审核通过，审核失败，如果店铺设置有实名奖励的话，需要给用户赠送金额

该模块负责管理 C 端用户的实名认证功能。

> **⚠️ 核心业务声明与注意事项**：
>
> 1. **权限移交**：A 端（平台端）不参与实名认证的审核，该功能全部下放给 B 端（商家端）。B 端的店长和业务员均可操作审核。
> 2. **数据隔离**：B 端在获取实名认证列表以及进行审核时，**必须且只能**操作归属于本店铺的 C 端用户（需关联查询 `customer_relation` 表）。
> 3. **实名奖励联动**：当审核通过时，系统必须检查该用户所属店铺的配置 (`shop_setting.real_name_reward`)。如果不为 0，则自动向该用户的钱包 (`user_wallet.voucher_balance`) 发放奖励，并生成一条资金变动流水 (`user_wallet_log`)。必须使用数据库事务 (Transaction) 保证原子性。
> 4. **敏感信息处理**：用户的身份证号 (`id_card_no`) 在落库时必须进行加密存储，在 B 端列表展示和 C 端回显时再进行解密。

## 涉及的数据表

- `user_identity`: 实名认证主表（存储认证资料、审核状态、驳回原因等）
- `customer_relation`: 客户关系表（用于判断 C 端用户归属于哪个 B 端店铺，进行数据隔离）
- `shop_setting`: 店铺配置表（用于读取 `real_name_reward` 实名奖励金额）
- `user_wallet`: 用户钱包表（审核通过发放奖励时，更新 `voucher_balance` 代金资产）
- `user_wallet_log`: 钱包流水表（发放奖励时记录资金变动）
- `sys_user`: 账号总表（用于在列表中展示用户的基本信息如账号、昵称）

## B端 (Admin-Outer) 接口

### 1. 获取本店实名认证列表

- **路径**: `GET /api/admin-outer/user-identities`
- **描述**: B端商家（店长/业务员）查看**归属于本店铺**的 C端用户的实名认证列表。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Query)**:| 字段名       | 类型   | 必填 | 描述                                  |
  | ------------ | ------ | ---- | ------------------------------------- |
  | page         | int    | 否   | 页码，默认1                           |
  | page_size    | int    | 否   | 每页数量，默认10                      |
  | audit_status | int    | 否   | 审核状态: 0未提交,1待审核,2通过,3驳回 |
  | real_name    | string | 否   | 真实姓名 (模糊搜索)                   |
  | username     | string | 否   | 用户名 (模糊搜索)                     |

### 2. 审核实名认证 - 通过

- **路径**: `POST /api/admin-outer/user-identities/:id/audit-success`
- **描述**: 店长或业务员审核通过用户的实名认证。若本店铺配置了实名奖励 (`shop_setting.real_name_reward > 0`)，会自动给该用户的钱包 `voucher_balance` 增加奖励金额并写入流水。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **路径参数 (Params)**:
  - `id` (Long, 必填): `identity_id`
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "审核通过操作成功"
  }
  ```

### 3. 审核实名认证 - 驳回

- **路径**: `POST /api/admin-outer/user-identities/:id/audit-fail`
- **描述**: 店长或业务员审核驳回用户的实名认证。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **路径参数 (Params)**:
  - `id` (Long, 必填): `identity_id`
- **请求参数 (Body)**:| 字段名        | 类型   | 必填 | 描述     |
  | ------------- | ------ | ---- | -------- |
  | reject_reason | string | 是   | 驳回原因 |
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "驳回操作成功"
  }
  ```

## C端 (Mobile) 接口

### 1. 获取当前登录用户实名状态 (回显)

- **路径**: `GET /api/mobile/users/identity`
- **描述**: C端用户获取自己的实名认证状态及数据回显（含驳回原因等）。
- **请求头 (Headers)**:

  - `Authorization`: `Bearer <token>`
- **响应数据示例**:

  ```json
  {
    "code": 200,
    "message": "获取成功",
    "data": {
      "audit_status": 1, 
      "reject_reason": null,
      "real_name": "张三",
      "id_card_no": "35010219900101XXXX",
      "id_card_front": "http://xxx/front.jpg",
      "id_card_back": "http://xxx/back.jpg",
      "hand_id_card": "http://xxx/hand.jpg"
    }
  }
  ```

  *(注: `audit_status` 0未提交，1待审核，2审核通过，3审核驳回)*

### 2. 提交实名认证资料

- **路径**: `POST /api/mobile/users/identity`
- **描述**: C端用户提交实名认证资料。若被驳回可重新调用此接口提交。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:| 字段名        | 类型   | 必填 | 描述              |
  | ------------- | ------ | ---- | ----------------- |
  | real_name     | string | 是   | 真实姓名          |
  | id_card_no    | string | 是   | 身份证号码        |
  | id_card_front | string | 是   | 身份证正面图片URL |
  | id_card_back  | string | 是   | 身份证反面图片URL |
  | hand_id_card  | string | 否   | 手持身份证图片URL |
- **响应数据**:
  ```json
  {
    "code": 200,
    "message": "提交成功"
  }
  ```

# 任务与任务商品

A端不参加
B端 增删改查

> **⚠️ 核心业务声明与注意事项**：
>
> 1. **A端不参与**：任务管理完全由B端店铺自己维护，平台总后台不提供任务管理功能。
> 2. **数据隔离机制**：
>    - 店长 (`isShopOwner === true`)：可以管理本店铺的所有任务。
>    - 业务员：一般无权限或只能查看（具体视按钮权限而定，但数据域仅限本店）。
> 3. **任务线 (ShopTask) 规则**：
>    - 每个任务包含基础属性（名称、最低接取金额、收益率等）。
>    - 一个任务线下可以配置多个子任务节点（`shop_task_item`），按顺序执行。

> **涉及的数据表**
>
> - `shop_task`: 店铺任务线主模板表
> - `shop_task_item`: 任务线子任务明细表
> - `shop_task_user`：用户绑定任务模板表 (B端给C端绑定)
> - `shop_task_user_item_progress`：绑定的子项表 (充当C端任务订单记录的核心表)
> - `user_wallet`: 用户钱包表 (用于扣减金额、发放收益及记录流水)
> - user_order: 用户订单表

## B端 (Admin-Outer) 商家操作

### 1. 任务列表

- **路径**: `GET /api/admin-outer/tasks`
- **描述**: B端获取本店任务列表。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Query)**:| 字段名    | 类型   | 必填 | 描述               |
  | --------- | ------ | ---- | ------------------ |
  | page      | int    | 否   | 页码，默认1        |
  | page_size | int    | 否   | 每页数量，默认10   |
  | task_name | string | 否   | 任务名称模糊搜索   |
  | status    | int    | 否   | 状态 0:停用 1:启用 |

### 2. 任务详情

- **路径**: `GET /api/admin-outer/tasks/:id`
- **描述**: B端获取任务详情，包含主任务信息及其子任务明细 (`items`)。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数**: 无

### 3. 新建任务

- **路径**: `POST /api/admin-outer/tasks`
- **描述**: B端新建一条任务线。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:| 字段名            | 类型   | 必填 | 描述                                     |
  | ----------------- | ------ | ---- | ---------------------------------------- |
  | task_name         | string | 是   | 任务名称                                 |
  | min_amount        | number | 是   | 最低金额（用户启动任务最低金额）         |
  | yield_rate        | number | 是   | 任务收益率（百分比，完成任务后用户所得） |
  | parent_yield_rate | number | 是   | 上级收益率（百分比，给上级返佣的收益率） |
  | task_type         | int    | 是   | 类型：0默认，1自定义                     |
  | status            | int    | 是   | 状态：0禁用，1启用                       |
  | check_parent      | int    | 是   | 是否校验上级：0否，1是                   |
  | daily_update_type | int    | 是   | 每日任务更新：0手动，1自动               |
  | lucky_team_assign | int    | 是   | 幸运订单团队奖励分配：0不分配，1分配     |
  | task_count        | int    | 是   | 任务数量                                 |
  | balance_min_rate  | number | 是   | 余额最小使用率（百分比）                 |
  | balance_max_rate  | number | 是   | 余额最大使用率（百分比）                 |

> 备注：新建任务时，系统会自动根据 `task_count` 的数值，循环生成对应数量的子任务(`shop_task_item`) 节点数据。

### 4. 修改任务

- **路径**: `PUT /api/admin-outer/tasks/:id`
- **描述**: B端修改任务线。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**: 同新建任务，所有字段可选。

### 5. 删除任务

- **路径**: `DELETE /api/admin-outer/tasks/:id`
- **描述**: B端删除任务线 (逻辑删除)。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数**: 无

### 6. 修改任务子项 (配置幸运订单)

- **路径**: `PUT /api/admin-outer/tasks/items/:item_id`
- **描述**: B端修改任务子项的具体配置，如设置为幸运订单及智能/手动匹配规则。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)** (所有参数均非必填，传哪个更新哪个):| 字段名         | 类型   | 描述                                             |
  | -------------- | ------ | ------------------------------------------------ |
  | is_lucky_order | int    | 是否为幸运订单，0=否，1=是                       |
  | yield_rate     | number | 收益率                                           |
  | rule_type      | int    | 规则类型，仅幸运订单有效：1=智能匹配，2=手动匹配 |
  | append_amount  | number | 追加金额，仅智能匹配有效                         |
  | goods_price    | number | 商品价格，仅手动匹配有效                         |
  | goods_title    | string | 商品标题，仅手动匹配有效                         |
  | goods_id       | int    | 商品ID，仅手动匹配有效                           |

### 7. 获取所有商品列表 (不分页)

- **路径**: `GET /api/admin-outer/goods/all`
- **描述**: B端获取可用于手动匹配任务的商品列表 (通常用于下拉框选择，不分页，只返回上架商品)。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Query)**:| 字段名     | 类型   | 必填 | 描述                                 |
  | ---------- | ------ | ---- | ------------------------------------ |
  | keyword    | string | 否   | 商品名称模糊搜索                     |
  | goods_type | int    | 否   | 商品类型过滤：1=普通商品，2=任务商品 |
  | min_price  | number | 否   | 最小价格查询                         |
  | max_price  | number | 否   | 最大价格查询                         |

### 8. 给用户绑定任务模板

- **路径**: `POST /api/admin-outer/tasks/bind-user`
- **描述**: B端店长给指定C端用户绑定任务模板。写入 `shop_task_user` 表，绑定后任务状态为“已绑定”。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:| 字段名  | 类型 | 必填 | 描述          |
  | ------- | ---- | ---- | ------------- |
  | user_id | int  | 是   | 目标C端用户ID |
  | task_id | int  | 是   | 任务模板ID    |

### 9. 开启用户任务

- **路径**: `POST /api/admin-outer/tasks/start-user`
- **描述**: B端店长开启已绑定的用户任务。更改 `shop_task_user` 状态变为“任务进行中”，并自动初始化任务子项进度，生成批量数据写入 `shop_task_user_item_progress`。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Body)**:| 字段名  | 类型 | 必填 | 描述          |
  | ------- | ---- | ---- | ------------- |
  | user_id | int  | 是   | 目标C端用户ID |
  | task_id | int  | 是   | 任务模板ID    |

### 10. 获取用户绑定策略

- **路径**: `GET /api/admin-outer/customers/:id/policy`
- **描述**: B端获取指定C端用户当前绑定的任务策略（模板）详情及规则列表。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数 (Params)**:
  - `id` (int): 必填，C端用户ID

*(注：B端获取店铺所有任务订单记录的功能可通过 `shop_task_user_item_progress` 联表查询拓展)*

## C端 (Mobile) 用户操作

### 1. 搜索/获取可接任务

- **路径**: `GET /api/mobile/tasks/search`
- **描述**: C端用户获取当前店铺下，满足其可用余额(`min_amount`)、且启用的任务列表。
- **请求头 (Headers)**:
  - `Authorization`: `Bearer <token>`
- **请求参数**: 无
- **响应数据示例**:
  ```json
  {
    "code": 200,
    "message": "success",
    "data": {
      "sequence_no": 1,
      "task_status": 2,
      "wares": {
        "goods_id": 123,
        "goods_title": "商品标题",
        "price": 1000.00,
        "cover_image": "http://..."
      },
      "order": {
        "orderNo": "T1634567890123",
        "price": 1000.00,
        "backRate": 0.05,
        "parentBackRate": 0.01,
        "staticBackMoney": 50.00,
        "dynamicBackMoney": 10.00,
        "ruleType": 1,
        "cTime": "2023-10-18T12:00:00.000Z"
      },
      "is_lucky": 0
    }
  }
  ```
- **业务逻辑**:
  - `task_status` 状态说明：0=任务未开启，1=用户金额低于店铺配置内最低金额，2=用户已开启任务，3=用户已完成任务，4=任务订单未支付。
  - C端不能主动接取任务模板，需要B端绑定开启。
  - 触发后，会将 `shop_task_user_item_progress` 进度表中对应子项更新 `is_processing=1` 并写入抽取到的商品ID及生成的订单号。

### 2. 执行任务 (接单支付)

- **路径**: `POST /api/mobile/finishOrder`
- **描述**: C端用户支付并完成当前待处理的任务订单，同时计算发放用户的静态收益和上级的动态返佣。
- **请求头 (Headers)**:

  - `Authorization`: `Bearer <token>`
- **请求参数**:

  | 字段名  | 类型   | 必填 | 描述       |
  | ------- | ------ | ---- | ---------- |
  | orderId | string | 是   | 任务订单号 |
- **业务逻辑**:

  - 根据 `orderId` 查找 `shop_task_user_item_progress` 中处于 `is_processing=1` 且未支付 (`status=0`) 的子项。
  - 校验用户 `user_wallet` 余额是否足够支付。
  - 事务更新：更新该任务子项状态为已完成 (`status=1`, `is_processing=0`)。
  - 发放任务收益：给用户增加 `balance` 和 `static_income`。
  - 上级返佣：若用户有上级 (`inviter_user_id`)，计算动态返佣 (`orderAmount * parent_yield_rate`) 并发放给上级 (增加上级的 `balance` 和 `dynamic_income`)。

### 3. 获取任务订单详情 (C端)

- **路径**: `POST /api/mobile/orderMsg`
- **描述**: C端用户接取任务后，通过订单号获取该订单的详细信息，包含收益、需要支付的差额等。
- **请求头 (Headers)**:

  - `Authorization`: `Bearer <token>`
- **请求参数**:

  | 字段名  | 类型   | 必填 | 描述       |
  | ------- | ------ | ---- | ---------- |
  | orderId | string | 是   | 任务订单号 |
- **业务逻辑**:

  - `status`: 0=待支付，1=已完成
  - `needPrice`: 如果商品总金额 (`totalPrice`) 大于用户余额 (`balance`)，则返回差额；否则为 0。
  - `orderType`: 1=普通订单任务, 2=幸运订单任务

### 4. 获取用户任务统计信息 (C端)

- **路径**: `GET /api/mobile/getUserTaskInfo`
- **描述**: 获取当前用户的余额、今日收益、昨日收益以及已完成订单数量等统计信息。
- **请求头 (Headers)**:

  - `Authorization`: `Bearer <token>`
- **请求参数**: 无
- **业务逻辑**:

  - 从 `shop_task_user_item_progress` 聚合查询今日及昨日 `status=1` (已完成) 订单的 `revenue` 计算收益。
  - 统计该用户当前 `status=1` 订单总数，及任务模板配置的总量。

### 5. 获取任务订单列表 (C端)

- **路径**: `GET /api/mobile/orders`
- **描述**: 获取当前用户的任务订单历史列表，支持按状态筛选。
- **请求头 (Headers)**:

  - `Authorization`: `Bearer <token>`
- **请求参数 (Query)**:

  | 字段名    | 类型 | 必填 | 描述                          |
  | --------- | ---- | ---- | ----------------------------- |
  | status    | int  | 否   | 订单状态 (0=待支付, 1=已完成) |
  | page      | int  | 否   | 页码，默认 1                  |
  | page_size | int  | 否   | 每页数量，默认 10             |
- **业务逻辑**:

  - 数据来源于 `shop_task_user_item_progress` 表。
  - 联表查询商品信息及配置的收益率并分页返回。

# 策略管理接口文档

策略管理模块用于配置用户的任务派发规则及收益参数。每个策略下可包含多条规则（Task Rules），这些规则决定了用户接单时的商品金额、返佣比例及任务特殊属性（如连单、幸运单）。

## 关联数据库表

- **strategies**: 策略主表，存储策略的基础配置（如收益率、任务总数、接单金额范围）。
- **strategy_rules**: 策略规则表，存储每单任务的具体执行细节（如指定商品、指定金额、特殊返佣率）。
- **users**: 用户表，通过 `strategy_id` 字段与策略绑定。

---

## 1. 策略列表与查询

### 获取策略列表
**接口地址**：`GET /api/admin/strategies`
**接口描述**：管理端分页查询策略列表，支持多条件筛选。

**请求参数 (Query)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| keyword | String | 否 | 策略名称关键词 |
| type | Integer | 否 | 策略类型：0默认，1自定义 |
| status | Integer | 否 | 状态：0启用，1禁用 |
| page | Integer | 否 | 页码（默认 1） |
| page_size | Integer | 否 | 每页数量（默认 10） |

### 获取策略详情
**接口地址**：`GET /api/admin/strategies/:id`
**接口描述**：查询指定策略的详细信息。如果策略配置了任务数（`task_count > 0`）但尚未生成规则，系统会自动在后台生成默认的规则项并返回。返回的数据中包含 `list` 数组（规则列表）。

### 获取用户当前策略
**接口地址**：`GET /api/admin/getUserPolicy`
**接口描述**：查询指定用户当前绑定的策略。如果用户未绑定策略，则自动返回系统的默认策略（`type=0`）。

**请求参数 (Query)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| userId | String | 是 | 用户ID 或 用户编码 |

## 2. 策略维护 (CRUD)

### 创建策略
**接口地址**：`POST /api/admin/strategies`
**接口描述**：新增一条策略配置，创建后系统会根据传入的 `task_count` 自动生成对应的空白规则记录。

**请求参数 (Body)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| name | String | 是 | 策略名称 |
| profit_rate | Decimal | 是 | 默认收益率 |
| task_count | Integer | 是 | 任务单数 |
| min_amount | Decimal | 是 | 接单最低金额 |
| min_usage_rate | Decimal | 是 | 余额最低使用率 |
| max_usage_rate | Decimal | 是 | 余额最高使用率 |
| ... | ... | ... | 其他业务参数详见数据模型 |

### 更新策略
**接口地址**：`PUT /api/admin/strategies/:id`
**接口描述**：修改策略的基础参数。
*特殊逻辑*：
1. 如果将策略设为默认（`type: 0`），系统会自动将其他策略置为自定义。
2. 如果修改了 `profit_rate`，系统会同步更新旗下所有未单独指定收益率的规则项。
3. 如果修改了 `task_count`，系统会智能增删规则项，以匹配最新的任务数。

### 删除策略
**接口地址**：`DELETE /api/admin/strategies/:id`
**接口描述**：物理删除指定策略，并级联删除该策略下的所有规则项（StrategyRules）。系统默认策略不允许被删除。

---

## 3. 策略规则项维护

### 更新策略规则项
**接口地址**：`PUT /api/admin/strategies/:id/rules/:ruleModelId`
**接口描述**：修改策略下某一单（特定规则项）的具体执行参数，例如设置指定商品、指定金额或特殊收益率。

**请求参数 (Body)**：
| 参数名 | 类型 | 描述 |
| :--- | :--- | :--- |
| ruleType | Integer | 规则类型：0普通订单，1幸运订单 |
| matchType | Integer | 匹配类型：0手动匹配，1智能匹配 |
| adminSetWaresName | String | 指定商品名称 |
| adminSetPrice | Decimal | 指定商品金额 |
| backRate | Decimal | 此单专属收益率 |
| isTrriger | String | 触发状态（'0'或'1'） |
| isRun | String | 执行状态（'0'或'1'） |

---

## 4. 用户任务与策略绑定

### 获取用户当前绑定策略
**接口地址**：`GET /api/admin/getUserPolicy`
**接口描述**：获取指定用户当前绑定的策略详情及其下的所有规则项。如果用户未绑定策略，则会返回系统中默认的策略（`type=0`）。

**请求参数 (Query)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| userId | String | 是 | 用户ID 或 用户编码 |

**返回数据说明**：
返回数据包含策略的基础信息，并带有一个 `list` 数组，数组中为格式化为驼峰命名规范的规则项（StrategyRules）。

### 绑定用户策略
**接口地址**：`POST /api/admin/bindUserPolicy`
**接口描述**：管理端绑定用户策略。用户新建时绑定type为0的策略（但任务不开启），在绑定新策略后，会重置任务状态（`is_task_started = false`）。

**请求参数 (Body)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| userId | String | 是 | 用户ID 或 用户编码 |
| strategyId | Integer | 是 | 策略ID |

### 开启用户任务
**接口地址**：`POST /api/admin/startUserTask`
**接口描述**：管理端开启用户任务。要求用户已绑定非默认策略（`type != 0`），开启后更新用户的任务状态（`is_task_started = true`），用户方可开始接收任务。

**请求参数 (Body)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| userId | String | 是 | 用户ID 或 用户编码 |

### 获取用户任务开启状态
**接口地址**：`GET /api/admin/getUserTaskStatus`
**接口描述**：管理端获取用户任务是否开启。

**请求参数 (Query)**：
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| userId | String | 是 | 用户ID 或 用户编码 |

**返回参数**：
| 参数名 | 类型 | 描述 |
| :--- | :--- | :--- |
| is_task_started | Boolean | 任务是否开启：`false`-未开启 `true`-已开启 |

一、Python 中 snake_case 规范细节
  ‌核心规则‌：全小写字母，单词间用单个下划线分隔，不能以数字开头，避开Python关键字。
  ‌适用范围‌：变量名、普通函数名、模块文件名，类名需遵循PascalCase规范。
  ‌特殊变体‌：常量使用全大写蛇形命名，如MAX_RECHARGE_LIMIT。
  ‌避坑要点‌：不要使用连续下划线、首尾无意义下划线，避免和Python标准库模块重名。
二、SQL 中 snake_case 规范细节
  ‌核心规则‌：全小写英文单词，下划线分隔，禁止驼峰、中横线写法。
  ‌约定后缀‌：时间类字段加_at、操作人类字段加_by、关联ID类字段加_id，布尔字段用is_/has_前缀。
  ‌避坑要点‌：避开数据库保留字，不用模糊的info/data这类无明确业务含义的字段名。
三、跨栈命名冲突避免方案
  ‌统一映射规则‌：在ORM层配置自动转换，避免手动逐个字段映射的冗余代码。
  ‌工具自动校验‌：Python项目用flake8-naming插件自动检查命名合规性，提前发现不规范命名。
  ‌全局配置兼容‌：对接不同命名风格的第三方接口时，可通过全局序列化配置统一风格，减少单字段手动适配的工作量。

规则1：管理端所有获取列表的接口，列表的是返回所有包括禁用状态的账号，删除时候才从列表内删除；
规则2：管理端所有带分页查询的列表接口，分页查询默认返回10条数据，最大返回100条数据，分页参数为page和pageSize，默认值为page=1,pageSize=10，分页参数为整数， 不能小于1，不能大于100，返回数据格式为：{total: 100, list: []}，total为总条数，list为当前页数据；
规则3：管理端所有查询/创建/更新/删除/查询/接口，需要传递角色参数，角色参数为整数，取值为1-3，1为管理员，2为主管，3为业务员;
规则4：如果在生成代码后，需要重启服务生效。就重启服务！；
规则5：权限树，管理员可以创建主管账号，主管可以创建业务员账号，业务员不能创建主管和业务员账号；
规则6：权限树，管理员可以增删改查所有账号，主管可以增删改查所有业务员账号需要关联主管账号，业务员只能查询自己的账号；
规则7：商城管理的权限只有管理员有，主管和业务员没有；
规则8：充值时候需要关联业务员，业务员id;

四、账号生成相关以及命名规范

  （一）管理员账号（admin_users 表）：
  - id: 自增主键（INTEGER.UNSIGNED），创建时自动生成，不可修改
  - username: 登录账号，STRING(64)，唯一，必填，支持管理端和移动端登录
  - nickname: 昵称，STRING(64)，可选
  - password: 登录密码，STRING(255)，加密存储
  - phone: 手机号，STRING(20)，可选
  - role: 角色，INTEGER，必填，默认3；取值：1管理员 2主管 3业务员
  - bind_salesperson_id: 主管绑定的业务员ID，INTEGER.UNSIGNED，关联admin_users.id
  - status: 账号状态，INTEGER，必填，默认1；取值：1启用 0禁用
  - 权限规则：管理员创建主管，主管创建业务员，角色向下受限

  （二）普通用户（users 表）：
  - id: 自增主键（INTEGER.UNSIGNED），创建时自动生成，不可修改
  - user_id: 用户ID，INTEGER.UNSIGNED，唯一，最少8位，现有库里不满足条件的都需要修改
  - username: 用户名，STRING(64)，唯一，默认使用手机号
  - phone: 手机号，STRING(20)，唯一，必填
  - nickname: 昵称，STRING(64)，可选
  - password: 登录密码，STRING(255)，加密存储
  - withdraw_password: 提现密码，STRING(255)，不加密存储
  - invite_code: 邀请码，STRING(64)，唯一，6位随机字符，创建时生成，不可修改
  - parent_id: 上级用户ID，INTEGER.UNSIGNED，关联users.id，用于邀请人关系链
  - salesperson_id: 绑定业务员ID，INTEGER.UNSIGNED，关联admin_users.id，用于归属业务员（提现/充值时标记业务员）
  - admin_id: 关联管理员ID，INTEGER.UNSIGNED，关联admin_users.id，当用户本身为业务员/主管时使用
  - admin_role: 关联管理员角色，INTEGER；取值：2主管 3业务员
  - status: 账号状态，INTEGER，必填，默认1；取值：1正常 0禁用
  - 注册规则：新建用户必须关联上级（salesperson_id或admin_id+admin_role），确保所有账号都有归属

  （三）邀请码（invite_code）规范：
  - 6位随机字符，全局唯一，不可重复，用于邀请新用户，格式为“随机数”，例如“105963”，全部随机不止最后一位随机
  - 创建账号时自动生成，后续不可修改
  - 使用邀请码注册的用户，其parent_id指向邀请人

  （四）归属业务员解析规则（提现/充值时使用）：
  - 优先级1：salesperson_id（直接绑定的业务员ID → admin_users.id）
  - 优先级2：admin_id + admin_role=3（自身即为业务员）
  - 优先级3：admin_id + admin_role=2（自身为主管）
  - 优先级4：沿parent_id递归查找上级的归属业务员

  （五）通用字段命名规范：
  - remark: 备注
  - status: 状态，取值统一为 0启用 1禁用（注：admin_users.status例外，为1启用 0禁用）
  - created_by: 添加人/创建人昵称
  - created_at: 创建时间，DATETIME，默认当前时间
  - updated_by: 更新人/修改人昵称
  - updated_at: 更新时间，DATETIME，默认当前时间
  - sort: 排序，数字越小越靠前，默认0
  - way: 方式名称（用于提现方式/充值方式）
  - _id后缀字段均为INTEGER.UNSIGNED类型，关联对应表的id主键

  （六）数据删除规则：
  - 所有管理端列表返回包含禁用状态的记录，不物理删除
  - 只有明确的删除操作才从数据库移除记录

{list: [], total: num}

六、提现佣金计算规则：
手续费3%，
”提现金额“=用户发起的金额
“手续费”=”提现金额“*3%
”用户到账金额“=“提现金额”-“手续费”

七、充值，提现记录
  - 订单号：唯一标识，用于查询和管理充值/提现记录，格式为字母+“随机数”，例如“TXA8Y6D”,9位数
  - 充值记录：用户充值记录，包含充值金额、手续费、用户到账金额、状态、创建时间等
  - 提现记录：用户提现记录，包含提现金额、手续费、用户到账金额、状态、创建时间等

# 后台管理系统 - 谷歌验证码 (2FA) 接口文档

本文档整理了管理端（后台系统）与谷歌验证码 (TOTP) 相关的所有接口。谷歌验证码主要用于提升账号安全，包括登录时的二次验证、敏感操作的安全确认，以及验证码自身的绑定与解绑（重置）。

---

## 1. 生成谷歌验证码 (仅生成不绑定)
用于生成该账号专属的 Base32 密钥，并返回二维码供用户通过谷歌验证器 (Google Authenticator) 扫码。**该接口为公开接口，无需登录（无需携带 Token）。** 注意：此接口仅生成密钥，不会直接绑定到用户账号，而是将密钥缓存到服务端（Redis），需在 5 分钟内调用绑定接口进行验证和绑定。

- **接口路径**: `POST /api/admin/generate-google-auth`
- **请求方式**: `POST`
- **请求参数 (Body)**:
  - `username`: `string` (必填) 当前管理员的登录账号
  - `password`: `string` (必填) 当前管理员的登录密码，用于安全校验。

### 响应示例
```json
{
  "code": 200,
  "message": "生成成功，请进行扫码并验证绑定",
  "data": {
    "qrCodeUrl": "data:image/png;base64,..."
  }
}
```

---

## 2. 绑定谷歌验证码
系统从缓存（Redis）中取出刚刚生成的 `secret`，并与用户在谷歌验证器中看到的 `code` 进行匹配验证。验证通过后才会真正将密钥保存至数据库，并清除缓存。如果验证失败，则直接丢弃缓存并提示重新获取。

- **接口路径**: `POST /api/admin/bindGoogle`
- **请求方式**: `POST`
- **请求参数 (Body)**:
  - `userName`: `string` (必填) 绑定的用户账号
  - `code`: `string` (必填) 谷歌验证器上的6位验证码

### 响应示例
```json
{
  "code": 200,
  "message": "谷歌验证码绑定成功",
  "data": null
}
```

---

## 3. 用户自行解绑谷歌验证码
用户在登录状态下，输入自己的登录账号和登录密码，解除账号的绑定状态。

- **接口路径**: `POST /api/admin/unbindGoogle`
- **请求方式**: `POST`
- **请求头**: `Authorization: Bearer <admin_token>`
- **请求参数 (Body)**:
  - `username`: `string` (必填) 当前管理员的登录账号
  - `password`: `string` (必填) 当前管理员的登录密码，用于安全校验。

### 响应示例
```json
{
  "code": 200,
  "message": "解绑成功，下次登录将不再需要验证码",
  "data": null
}
```

---

## 4. 重置管理员谷歌验证码 (上级强制解绑)

用于上级管理员或直属主管为下属重置（解绑）谷歌验证码，主要用于处理用户手机遗失或误删验证器 App 导致无法登录的情况。重置后，该账号的绑定状态变为 `false` (对应数据库字段设为 null)，下次登录不再需要验证码。

- **接口路径**: `POST /api/admin/users/:id/reset-google-auth`
- **请求方式**: `POST`
- **请求头**: `Authorization: Bearer <admin_token>`
- **路径参数**:
  - `id`: 需要重置的管理员（下属账号）ID

### 响应示例

```json
{
  "code": 200,
  "message": "重置谷歌验证码成功",
  "data": null
}
```

### 错误响应示例 (权限不足)

```json
{
  "code": 403,
  "message": "只能重置自己关联的业务员账号"
}
```

## 5. 登录接口中的谷歌验证逻辑

后台管理员登录接口 `/api/admin/login` 现在支持了谷歌验证码。

- 若当前账号**未绑定**谷歌验证码，登录时无需提供验证码即可直接登录成功，以方便首次使用时进入系统进行扫码绑定。
- 若当前账号**已绑定**谷歌验证码，则必须在请求体中附带 6 位的 `googleCode`，否则将无法登录。

### 涉及的请求参数

在 `POST /api/admin/login` 接口中：

| 参数名         | 类型   | 必填 | 说明                                                      |
| -------------- | ------ | ---- | --------------------------------------------------------- |
| `username`   | string | 是   | 管理员账号                                                |
| `password`   | string | 是   | 密码                                                      |
| `googleCode` | string | 否   | 6位谷歌动态验证码。**当账号为已绑定状态时为必填项** |

### 错误响应示例 (已绑定但未提供验证码 / 验证码错误)

```json
{
  "code": 422,
  "message": "谷歌验证码错误" // 或 "谷歌验证码不能为空"
}
```

## 6. 敏感操作时的谷歌验证逻辑

为了保护系统资金与参数配置安全，部分高危操作在调用时同样需要传入当前的谷歌动态验证码进行二次鉴权（即便用户已经登录）。这些接口在 Body 中统一接收 `googleCode`（驼峰命名） 或 `google_code`（下划线命名）参数。

目前涉及到验证 `googleCode` 的业务接口有：

1. **添加会员余额**: `POST /api/admin/members/add-balance`
2. **扣除会员余额**: `POST /api/admin/members/deduct-balance`
3. **充值请求审核成功**: `POST /api/admin/recharges/audit-success`
4. **充值请求审核失败**: `POST /api/admin/recharges/audit-fail`
5. **提现参数配置更新**: `PUT /api/admin/withdraw-config`

（在调用上述接口时，前端需要设计弹窗，要求管理员输入当前 6 位谷歌验证码，将其拼接到对应的请求参数中发送）
